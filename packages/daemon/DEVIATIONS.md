# WP8 (maker daemon) deviations from `docs/SPEC.md`

Same vocabulary as the other hand-over files. **Deviation** = differs from the text. **Choice** =
the text was silent and the smallest sound reading was taken. **Note** = built as written, but
the next package needs to know. **Gap** = specified, not (fully) built. Nothing outside
`packages/daemon/` was edited.

## Durable state and recovery (7.4, 7.6)

| # | Kind | What |
| --- | --- | --- |
| S1 | Choice | Intent life cycle: `planned` (row written before the action) → `sent` (written with the transaction id after signing and BEFORE the bytes leave) → `confirmed`/`failed`. A row found `planned` after a crash was never signed: it is failed and the state machine re-plans from finalized state. A `sent` row is looked up; found = confirmed; blockhash expired or nonce consumed = failed and re-planned; otherwise the swap waits. After 5 minutes (Solana) or 1 hour (Ethereum) unresolved it is parked `needs_review` with a critical alert and is still never re-sent, but it keeps being looked up, so a transaction that lands late is picked up. Transfers to third parties (`venue_transfer`, `xmr_send`) found unresolved at start are parked and never re-sent. |
| S2 | Choice | Monero: the lock is built with `do_not_relay`, stored, and relayed later from the stored bytes; a relay is repeated with the same bytes, so it cannot become a second payment. The sweep is built once (not published), stored, then published; a repeat publishes the stored bytes. |
| S3 | Choice | Coin control: every wallet output is kept frozen in wallet-rpc and only the output reserved for a swap (or the sources of a split or payment) is thawed while the transaction is built. `refills` is not a table: the rebalancer's snapshot and the adapters' state live in `kv`. |
| S4 | Deviation | Encryption private keys in the database are sealed with AES-256-GCM (Node's crypto) under a key derived from the keystore seed by HKDF, not with the core's `passphraseSeal` (scrypt per key would cost seconds per message). The keystore file itself uses `passphraseSeal` as specified. |

## Operator instructions (follow-up to the SDK's BUG-1)

An instruction is written to the swap's row (`facts.instruction`, with its flag in `facts.manual`) before anything acts on it, so it is honoured after a crash or restart; the crash matrix cuts at that point too (`instructed`). What the audit changed:

- **Abort in direction A once ready is set** was silently overtaken by the automatic claim. It is now refused with `ready-already-set`.
- **A refused instruction left its flag set** and could fire later when the state changed. Instructions are one-shot; the flag is cleared when the instruction settles. Exception: a refused *reject* (Solana take outside window mode) stays the decision, so the daemon does not fund a take the operator said no to; it lapses.
- **An instruction whose own transaction died** was forgotten. It now counts as carried out only when its transaction is confirmed, and is planned again otherwise.
- **Pause** did not stop an automatic approval whose verdict was already on record. While paused, a stored automatic "approve" is not acted on; the rules decide again and reject. An explicit approval by the operator is still honoured while paused.
- A standing "do not withhold this one" (`withhold: false`) is a policy override, not a one-shot instruction, and persists.

## BUG-3 and BUG-4 (tests/e2e/BUGS.md) and the audit that followed

- **BUG-4, root cause confirmed.** `prepareLock` thawed one output and let wallet-rpc choose; an output that had arrived since the last inventory pass was unfrozen and was added as a second input. Its key image was stored but it was not in the output table (so not reserved) and not frozen, so the next lock took it again. The node's refusal was then journaled `confirmed`, because the journal recorded "the call returned", not "the node accepted".
- **Fix, three layers.** (1) Every build (`lock`, `split`, `send`) runs a freeze pass inside the wallet section, reserves its inputs in the database before the wallet is asked, and refuses a result whose inputs are not exactly the reserved ones (the transaction is dropped unstored and unrelayed, the stray output frozen, the build repeated; after three tries nothing is built). Reservations stay until the wallet reports the output spent, and survive restarts and reorgs. (2) A relay the nodes refuse is journaled `failed`; only "accepted" or "the nodes already hold this transaction" is `confirmed`. (3) Before the notice, the stored lock's inputs must be unspent in the chain and the pool on the nodes asked and reserved for that swap alone; otherwise the lock is discarded and built again from another output, and if the nodes cannot be asked the notice waits.
- **Declined as written:** "never post a notice for a transaction the node has not accepted". SPEC 7.5 steps 4 and 5 (and scenario R-2: "no XMR was broadcast") require the reverse order: the XMR may be shown to a node only after the notice is final. The check in (3) covers every reason a node would refuse it without showing it the transaction. A lock whose input is spent by a third party after the notice still ends in an abort; nothing can prevent that.
- **BUG-3, root cause confirmed.** A pass already running settled an instruction journaled after it began. An instruction is now journaled inside the swap's own section, so a running pass finishes first and never sees it; and a pass may refuse only after it read the chain with the instruction on record. Otherwise it stays pending.
- **Audit, fixed.** Exposure limits, paying caps and unlocked outputs now count a swap from the moment it is approved (the row can read PENDING while the approval is in flight or not yet final), and the decision and its record are one section. The Ethereum operator's sends are serialised (two could sign one nonce). A byte-identical Solana transaction on the same blockhash is refused before it is recorded (its status lookup would have reported the earlier one's success). Offer passes no longer overlap (two could refill the same key slots). Transactions that belong to no swap (rotation, registry, pause, messages) were left `sent` until a restart; they are now looked up every minute and failed with an alert when they did not land.
- **Audit, no change needed.** Solana key-pool slots are assigned by the program; an Ethereum leaf two takers name is rejected with reason 2; one share per swap is created inside the swap's section.
- **Key-pool generation off the hot path** (reported by the web UI, apps/web DEVIATIONS). The Ethereum key pool was generated synchronously inside the offer pass: `eth_pool_size` proofs of about 0.2 s each, with nothing else running. It is now generated in the background, one proof per turn of the event loop, persisted as it goes (a restart resumes), and nothing waits for it: quoting goes on with the current pool until its replacement is complete, and the first direction-A Ethereum quote of a new daemon appears on the refresh after its first pool is ready. One proof (about 0.2 s) is still the longest single stall; a worker thread would remove that too and was not built. The one proof made at `fund` on Ethereum (direction B) is still inline.

## Price sources: the maker chooses (owner's decision; replaces "a wXMR pool is a cross-check only")

`docs/DESIGN.md` (Decisions table, "Price sources") and `docs/SPEC.md` 7.2 and interpretation 24 still state the old rule; they are the architect's to update. The daemon follows the new one.

- **What the file says is what runs.** Any of `coingecko`, `coinmarketcap`, `wxmr_pool`, `wxmr_pool_sol` may be a market's `source`, appear anywhere in `fallbacks`, or be the `cross_check`. Nothing is promoted, dropped or disabled.
- **Schema additions (backward compatible).** `cross_check` accepts `"none"`; each market may set its own `cross_check` (a source or `"none"`; absent = the global one); a second pool `[pricing.sources.wxmr_pool_sol]` with the same keys as `wxmr_pool`, SOL-quoted by default (`wxmr_pool` stays USDC-quoted by default; either can set `quote`).
- **Warnings (never blocking), exact text.** Pool as primary: `<source> is this market's primary price source: a thin pool can be pushed off-market cheaply by someone who then takes your quote`. No cross-check: `nothing checks this price against a second source`. No fallback: `quoting pauses whenever this source is unavailable`. Cross-check equal to the primary: `the cross-check is the primary source itself (<source>); it is treated as none: nothing checks this price against a second source`. Unreadable pool: `<pool> cannot be read yet: its addresses are placeholders or missing (base_vault and quote_vault are needed); it is skipped until they are set`; with nothing else to read the market stays off: `none of this market's price sources can be read yet: it stays off until the pool addresses are set`.
- **Errors, exact text** (enabled markets only; `<m>` is e.g. `eth sell_xmr`): `<m> needs ETH/USD; <source> cannot supply it — add coingecko or coinmarketcap as this market's source for ETH/USD, or disable the market`; `<m> needs XMR/SOL; <source> supplies XMR/USD and nothing here supplies SOL/USD — add coingecko or coinmarketcap as this market's source for SOL/USD, use a SOL-quoted pool (wxmr_pool_sol), or disable the market`; `<m> needs XMR/USD; <source> supplies XMR/SOL and nothing here supplies SOL/USD — add coingecko or coinmarketcap as this market's source for SOL/USD, use a USDC-quoted pool (wxmr_pool), or disable the market`; `<m> has a hard price band in USD; <source> gives XMR/SOL and nothing here supplies SOL/USD — add coingecko or coinmarketcap as this market's source for SOL/USD, or remove guardrails.price_band_usd`; `<pool> has min_liquidity_usd in USD; it is SOL-quoted and nothing here supplies SOL/USD — add coingecko or coinmarketcap as this market's source for SOL/USD, or set min_liquidity_usd = 0`; `<pool> is named but [pricing.sources.<pool>] is not in the file`. "This market's source" means its `source` or `fallbacks`: the asset's own USD price may come from another of the market's sources than the one that prices XMR.
- **The pool's protections, as built.** Before this change the pool price was the plain mean of the reads in the window and a single read was quoted at once; it is now a time-weighted average, unavailable until the window is filled (`average_seconds = 0` = the last read, the maker's explicit choice). Under `min_liquidity_usd` the source is unavailable at once (next fallback, or pause). `max_age_seconds`, the volatility pause, the hard price band and the stale pause apply to a pool primary as to any source. Per-read bound: with `guardrails.volatility_pause` set, a read more than `move_pct` away from the last accepted one is set aside and joins the average only after reads have stayed at the new level for `average_seconds`.
- **Only the sources in use are read.** A maker whose file names only the pool never calls CoinGecko or CoinMarketCap.
- **Refill through the bridge alone.** A `[rebalance]` with only `wxmr_bridge` enabled validates with no warning about other venues. Fixed on the way: the daemon never handed the bridge adapter its Solana connection, so the bridge venue was silently off outside tests.
