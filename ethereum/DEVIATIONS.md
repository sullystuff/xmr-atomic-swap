# WP3 deviations from `docs/SPEC.md` and the frozen interface

Recorded by work package 3 (Ethereum contract). Each row: the spec section or frozen artifact, what was built, and why. Nothing under `interfaces/` or `docs/` was edited; the contract is built to the frozen interface and `check-abi.mjs` passes.

"Deviation" = the contract differs from the text. "Vector" = a row of the frozen vectors that cannot be reproduced on Ethereum as written. "Choice" = the text was silent or ambiguous. "Note" = built as written, but the next package or the architect needs to know.

## Structure and build

| # | Spec | Kind | What was done | Why |
| --- | --- | --- | --- | --- |
| 1 | 5.1 "One contract, `XmrSwap`" | Deviation | Three code objects: `XmrSwap` (set-up, registry, views, one thin entry point per swap call), and two **linked libraries** `SwapOpen` (`lock`, `take`, EIP-712 digests) and `SwapSettle` (every other transition). The libraries run by DELEGATECALL in the proxy's context. Runtime sizes: `XmrSwap` 16,769 bytes, `SwapOpen` 13,651, `SwapSettle` 11,591. | As one contract the runtime code is 35,446 bytes, over the 24,576-byte limit of EIP-170 (lowering `optimizer_runs` to 1 only reaches 35,049). The ABI of `XmrSwap` is unchanged, the reentrancy guard stays in `XmrSwap`, and the libraries cannot be entered directly (the compiler's call protection; their own storage is empty). A deployment therefore deploys the two libraries, the implementation and the proxy; an upgrade deploys a new implementation linked to its libraries. `forge script` and `forge test` link automatically. |
| 2 | 5.1 `foundry.toml` | Note | `via_ir = true` (the spec allows it; `lock` has eleven parameters). `ffi = true`, used by one test only: it runs `cast wallet sign --data` (SPEC 9.1 asks for a signature produced by `cast`). `gas_limit` and `memory_limit` are raised for the replay tests. `fs_permissions` also grants read-write on `ethereum/deployments/`, where the deploy script writes its addresses. `allow_paths = ["../interfaces"]` and the remapping `xmrswap-interfaces/=../interfaces/` import the frozen interface without copying it. | |
| 3 | 5.1 "`ethereum/lib/` … vendored and committed (`forge install --no-git`)" | Choice | Installed with `forge install --no-git` at `forge-std@v1.17.0`, `openzeppelin-contracts@v5.7.0`, `openzeppelin-contracts-upgradeable@v5.7.0`, then pruned to the sources a build reads: `contracts/` (without `contracts/mocks/`) of the two OpenZeppelin repositories and `src/` of forge-std, each with its licence, `package.json` and README. No git submodule exists in the parent repository. | The full checkouts are about 50 MB of tests, docs, audits and nested submodules that no build uses. |
| 4 | 5.2 storage layout | Deviation | Done as M1 follow-up 5: a swap is stored as the packed `SwapStore.Record` (24 slots; `lock` writes 17 fresh slots instead of 22), with `amount`, `deposit` and `price` as `uint128`; `getSwap` still returns the frozen interface struct, so the ABI is unchanged. Amounts above `2^128 − 1` are refused with `AmountOutOfRange`, never truncated. The layout, and the gas before and after, are in `STORAGE.md`; it must not change once a proxy is deployed. `Maker` is stored as the interface struct. | `lock` went from 617,071 to 528,905 gas with ETH and from 672,712 to 564,646 with USDC. |

## Storage and registry

| # | Spec | Kind | What was done | Why |
| --- | --- | --- | --- | --- |
| 5 | 5.2, 5.3 "`setPaused`, `bumpEpochs`, `cancelQuote`, `revokeApproval`: maker owner or operator" (WP1 note E4) | Deviation | Added `mapping(address => address) makerOfOperator`. An operator address can serve one maker only: `registerMaker` and `setOperator` revert with `AlreadyRegistered` if the operator is already another maker's; a rotation frees the old address. The four functions act on the caller's own record if the caller is a registered maker, otherwise on the record it operates, otherwise `NotRegistered`. | The functions take no maker argument, so an operator must name exactly one record. Consequence: somebody can register a record that names a victim's intended operator address first; the victim then has to pick another operator key (keys are free; registration itself cannot be blocked this way). Overwriting the index instead would let an attacker redirect a victim's `setPaused` or `cancelQuote` to another record, which is worse. |
| 6 | 5.2 `volume`, `withheldVolume`: `uint256` | Deviation | Stored as `uint128`, saturating at `2^128 − 1`; `volumeOf` returns `uint256`. `responseSecsSum` saturates at `2^64 − 1`, counters at `2^32 − 1`. | The saturation sequence of `transitions.json` expects the volume to stop at `2^128 − 1`. |
| 7 | 5.3 `registerMaker`, `setPayout`, `initialize` | Choice | A zero operator, payout, treasury or USDC address is refused with `BadValue`. `setOperator` to the current operator is accepted and still bumps both epochs. | A zero payout would burn claims; the text names no error. |
| 8 | 5.3 `setSolanaLink` | Note | Built as Solana's `set_eth_link`: a matured pending link is promoted first; with no link and none pending the new one is set at once; otherwise it is recorded with `solanaOwnerNextAt = now + 604,800` (zero = unlink). Promotion happens only inside `setSolanaLink`. `getMaker` returns the raw record, so readers apply "the pending value is current once `now >= solanaOwnerNextAt`" themselves. | |

## Opening (`lock`, `take`)

| # | Spec | Kind | What was done | Why |
| --- | --- | --- | --- | --- |
| 9 | 5.3 check order of `lock` | Deviation | Order: swap id unused (`BadState`); maker registered, not paused; quote signature; `validUntil`; epoch; cancelled; direction; `q.taker`; token; price tiers; depth tiers; `minXmr <= xmr <= maxXmr`; amount and `maxPay`/`minReceive`; approval mode and advance approval; the bounds of 3.1 in the order of `deadlines.json`; `openPending`; then (lock) the taker's view share and the pool leaf; then the taker's keys; then funds. | The reference model fixes `ApprovalRequired` before the bounds and the bounds before `TooManyPending`; the spec lists the bounds before the approval. Every vector violates one rule only, so only the relative order of those three is observable. |
| 10 | 3.1, WP1 C12, and the rows "depth zero → `DepthInvalid`" and "amount zero → `AmountOutOfRange`" | Deviation | A quote whose first depth tier is unused (`depth[0] == 0`) fails with `DepthInvalid` at the depth bound, and one whose first price tier is unused (`tierPrice[0] == 0`) has no price, so its amount is zero and it fails with `AmountOutOfRange`. Every other malformed tier set (price or depth) is `TiersInvalid`. | A quote has no other way to say "depth zero" or "amount zero for a whole XMR", and the transitions rows require those errors. The tier lookup itself (`SwapMath.tierValue`) still reports a zero first tier as malformed, as `amounts.json` has it. |
| 11 | 3.8, 5.3 "mode 2 requires a valid `Approval` …, otherwise pass an empty signature" | Choice | An advance approval is verified whenever `approvalSig` is not empty, whatever the mode; an invalid one fails the call. Effective `mode`: 3 if the quote is taker-bound; else 0 for `approvalMode` 0; 2 for `approvalMode` 1 or 2 with an approval; 1 for `approvalMode` 1 without. `approvalMode` 2 without an approval is `ApprovalRequired`, unless the quote is taker-bound (the maker signed for that taker). `approvalMode > 2` is `BadState` (the model's rule for an unknown offer mode). | Matches the `mode` values of the vectors (WP1 M5). |
| 12 | 2.10 approval errors | Choice | As `eip712.json` fixes them: wrong maker or taker `WrongParty`; token `TokenNotAllowed`; direction `WrongDirection`; size `AmountOutOfRange`; before `notBefore` or after `validUntil` `Expired`; epoch `StaleEpoch`; revoked `Revoked`. Every signature failure, including a high-s or malformed signature, is `BadSigner` (`ECDSA.tryRecoverCalldata`, not `recoverCalldata`, whose own errors are not in the interface). | |
| 13 | 5.3 inputs the text does not bound | Choice | `xmr == 0` or `amount == 0` is `AmountOutOfRange` (`SwapMath.swapAmount`; direction B rounds down), now also the model's rule and in the vectors (`amounts.json` op `swap`). A price or an amount above `2^128 − 1` is `AmountOutOfRange` (the model's `MathOverflow`, which is not an Ethereum error, WP1 E7). Taker `spendPub`, `key`, `key2` or `encKey` zero is `BadKey`; a zero `spendPub` in `fund` or in the leaf is `BadKey`. In `take` the taker's `viewShare` must be zero (`ViewInvalid`). A session budget with a zero session key, or one the session key does not accept within 30,000 gas, is `BadValue`. A notice ciphertext that is not 104 bytes is `BadValue`. `reject` with a reason above 2 is `BadState` (WP1 M7). `withdrawOwed` and `withdrawTreasury` to the zero address, and a pull whose ETH transfer fails, are `BadValue`. | |
| 14 | 5.3 "`q.keyRoot`: zero for direction B" | Note | Not enforced; `take` ignores `keyRoot`. | |

## Settlement

| # | Spec | Kind | What was done | Why |
| --- | --- | --- | --- | --- |
| 18 | 3.5 B11 "`amount` parked for the maker (`owed_maker`)", WP1 M11 | Choice | Parked payouts are keyed by the address the push would have gone to: the payout address for a direction-A claim, the current operator for a direction-B refund. B11 (`expireUnnoticed`) parks the maker's escrow for the **maker's owner address** (the registering key), which pulls it with `withdrawOwed`. | Solana lets the owner key pull `owed_maker`; after 30 idle days the hot key may be gone. | 19 | 3.6 `withhold`: "Otherwise no evidence" (WP1 M8) | Choice | Where no evidence is required it is neither checked nor stored; the event carries the arguments as passed. | 20 | 5.5 events | Choice | A7a emits `Aborted` with `newState = 9` (DONE). B11 emits `ExpiredUnnoticed` and a `PayoutDeferred` for the parked escrow. `Locked.leaf` is the leaf hash (zero in direction B). `EvidencePublished` carries counter `0xff`. | The section abbreviates. |
| 21 | 5.4 "ETH is sent with a 30,000 gas stipend" | Note | Built as written. If the transaction itself is sent with too little gas for the stipend, the push fails and the payout is parked rather than paid; the call still succeeds and the recipient pulls it. A third party can provoke that by front-running a claim or refund with a starved copy; it costs the recipient one `withdrawOwed`. A gas floor before the push would turn that into a revert of a call that carries a secret, which 5.4 forbids. | For the audit list. |
| 22 | 5.3 `hashQuote`, `hashApproval`, `version` | Note | The digests are computed in `SwapOpen` with the domain separator rebuilt from the constants `("XmrAtomicSwap", "1")`, `block.chainid` and the proxy address; a test checks it equals `EIP712Upgradeable`'s and the vectors'. `version()` is `view`, as the frozen ABI has it, and returns `"1"`. | The library cannot reach `EIP712Upgradeable`'s internal functions. |

## For the SDK (WP5) and the end-to-end harness (WP11)

- **Deploying.** `forge script script/DeployAnvil.s.sol --rpc-url http://127.0.0.1:8545 --broadcast --unlocked --sender <an anvil account>` deploys the libraries, the implementation, the proxy and a mock USDC (6 decimals, `mint`, `setBlacklisted`, `setPaused`), and writes `ethereum/deployments/anvil.json` (`chainId`, `proxy`, `implementation`, `usdc`, `owner`, `treasury`). It refuses every chain id but 31337. The bytecode of `XmrSwap` has link placeholders; deploying it by hand needs the two library addresses.
- **Every swap starts PENDING**, in both directions; the maker's `approve`/`fund` must carry the swap's `openHash` (read it from `getSwap`, or compute it with `openHashEthereum`).
- **Callers.** `claim` and `refund` are open to anyone. `setReady` is the locker's (A: taker wallet or session key; B: operator). `postNotice`, `abort` and `publishEvidence` are the claimer's (A: operator; B: taker wallet or session key). `cancelPending` is the taker wallet's or the session key's.
- **Check order and error names** are those of `transitions.json`: direction, caller, state and open hash, time, then secret or evidence. An unknown swap id is `BadState`.
- **Parked payouts.** Listen for `PayoutDeferred(token, account, amount)` and read `owedOf(token, account)`; the account itself calls `withdrawOwed(token, to)` and may name another destination. See row 18 for which account that is.
- **A pool share is consumed at `approve`**, by `keyAddr`. Two pending locks may name the same leaf; the second `approve` fails with `KeyAlreadyUsed` and the daemon rejects with reason 2. `lock` already refuses a leaf whose key is consumed.
- **Flags** (`Swap.flags`): 1 notice on record, 2 evidence on record, 4 a secret is revealed (`Swap.revealed`), 8 revealed by the locker (a refund), 16 late notice.
- **Tests and time.** With `via_ir` the optimizer may reuse an earlier `block.timestamp` after `vm.warp` inside one test function; test code should read the clock with `vm.getBlockTimestamp()`. Arguments of a pranked call that themselves make a call (a `sha256`, a view) must be computed before `vm.prank`.
- **Gas** (a whole transaction, `forge test --isolate --match-contract GasTest -vv`): the table is in `STORAGE.md`; `lock` is the expensive call.
