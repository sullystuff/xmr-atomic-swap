# WP1 deviations from `docs/SPEC.md`

Recorded by work package 1 while building M0. Each row: the spec section, what was built instead, and why. The architect folds these back into the spec; nothing here changes a protocol rule unless it says so.

"Deviation" = the artifact differs from the text. "Choice" = the text was silent or ambiguous and the smallest sound reading was taken. "Note" = built as written, but the next package needs to know.

## Reference model (`swap_core::model`) and `transitions.json`

These are conventions the contracts MUST share with the model, because the vectors encode them.

| # | Spec | Kind | What was done | Why |
| --- | --- | --- | --- | --- |
| M1 | 3.4 to 3.6 (no order given) | Choice | Check order: direction, caller, state (and open hash), time gate, then secret or evidence. Every rejected row in the vectors violates one rule only, except where noted here. | Vectors need one expected error. |
| M2 | 3 (`TooEarly`, `TooLate` not defined) | Choice | A call refused only because of the time is `TooLate` if one of its windows in that state has already closed, else `TooEarly`. Example: `refund` in NOTICED during `[T_co, T_exp)` is `TooLate`; `claim` in ABORTED before `T_final` is `TooEarly`. | Same reason. |
| M3 | 3.2 "every row gated by `T_note`, `T_cut`, `T_co` or `T_cd` is also refused when `now >= T_final`" | Choice | Applied to rows with an **upper** gate (`now < T`). Rows that open at `T_note` and have no upper gate (A8, A10g, B9b) stay enabled after `T_final`. | Read literally, a taker in ACTIVE (A) would have no exit after `T_final` and a maker in ACTIVE (B) would be stuck until B11, which contradicts invariant 2. For upper-gated rows the extra check is unreachable, as the text says. |
| M4 | 3.4, 3.5 outcome "closed" | Choice | The model ends these rows in DONE and reports `closed = true` when nothing was parked. Solana closes the account in the same instruction (state then reads 0); Ethereum keeps DONE. | One model for both chains. |
| M5 | 4.2 `mode`: "Effective mode: 0 auto, 1 window, 2 advance, 3 quote" | Choice | 3 for a quote; 2 when a valid approval is presented on a WINDOW or ADVANCE offer; otherwise the offer's mode (an approval presented on an AUTO offer leaves 0). Only "is it 1" changes behaviour. | The table of 3.8 says such swaps are "treated as AUTO" but the field has four values. |
| M6 | 3.5 B3 "window mode only" | Choice | `reject` on a direction-B swap outside window mode on Solana fails with `BadState`. `approve` in B, `fund` in A, `refund_unnoticed` in B and `expire_unnoticed` in A fail with `WrongDirection`. | No error is named. |
| M7 | 3.7 `reject` reason "0, 1 or 2" | Note | A reason above 2 is not representable in the model and not in the vectors. The contracts should refuse it; which error is theirs to choose (`BadState` is suggested). | |
| M8 | 3.6 `withhold`: "Otherwise no evidence" | Choice | Where no evidence is required (direction B, or A without a notice on record), supplied evidence is ignored. Not covered by vectors. | Either reading is safe for funds. |
| M9 | 3.3 `deposit_state` | Choice | `release_deposit` from HOLD sets 3 (returned) whoever calls; from WITHHELD sets 4 (released by the maker); `split_deposit` sets 5. `t_refund` is written by every keyed refund; `t_settled` when the swap reaches DONE; `outcome` is the counter of the transition that reached DONE. | The values are listed but not assigned to rows. |
| M10 | 2.12 `Env` | Choice | `Env` also carries the maker's `open_pending`, so `MAX_OPEN_PENDING` is modelled (`TooManyPending`). Sequences track a `MakerRecord` (counters, sums, `open_pending`) with saturating updates. | "A counter at `u32::MAX`" needs the maker record in the model. |
| M11 | 5.4 "Fees and treasury halves only increment `treasuryAccrued`" | Note | In Ethereum rows the treasury share is listed as a payout to `treasury` with `parked: false`; that means "accrued". `withdraw_owed` in the model is called by `taker` (the wallet), `owner` (Solana: the maker's owner key; Ethereum: the account the payout is owed to) or anyone for the treasury (Solana). | One payout vocabulary for both chains. |
| M12 | 3 | Choice | A payout of zero is not listed (fee of a tiny amount, a zero deposit). B11 always parks the maker's `amount`. `publish_evidence` needs a notice on record and moves no counter (`0xff` in events). | |

## Open risks this package closed

- The `wasm-bindgen` + `getrandom/js` build of the DLEQ code runs in Node 22 and in Chromium 151 (prove and verify about 210 ms each in the tab); each build verifies the other's proofs.
- The nodejs wasm target works behind an ES-module wrapper.
- A viem signing round trip reproduces the vector signatures byte for byte.
- EIP-712 fixed-size arrays: see E6.
- `anchor idl build` works with the root `rust-toolchain.toml` present, and the IDL it produces from the skeleton is the frozen one (`check-idl.mjs` passes on a fresh build).
